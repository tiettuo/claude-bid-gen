# P2.1: 历史方案匹配与抽取系统 — 方案设计

> 日期：2026-05-17
> 状态：方案讨论完成，待数据到位后实施
> 来源：Round 10 路线图 P2 中期规划

---

## 一、目标

用已有的几千份历史投标方案作为"模板库"，新项目来时：
1. **匹配**：按项目类型+地区+工种+清单预算，自动找到最相似的历史方案
2. **抽取**：从匹配的方案中提取可复用的章节/小节模板（LLM 泛化去项目特征）
3. **替换**：自动填充新项目的变量（名称/地点/金额/工期/海拔等）
4. **校验**：LLM 一次性检查所有章节，标注问题而非重写

**核心转变：LLM 从"作者"降为"编辑"。**

---

## 二、架构

```
新项目 facts (类型/地区/海拔/工种/清单预算)
         │
         ▼
  ① 匹配引擎 (SQLite FTS5 查询)
     WHERE type ≈ 新项目 AND region = 新项目 AND trades 交集 > 0
     ORDER BY altitude_diff, project_similarity
     → Top-3 匹配项目
         │
         ▼
  ② 模板库 (本地目录)
     templates/
     ├── 通用套件/     ← 安全/质量/措施/文明施工（按地区变体）
     └── 分部分项/     ← 钢结构/混凝土/土方/给排水...（按工种+地区）
         │
         ▼
  ③ 变量替换 (规则引擎，不调 LLM)
     项目名/地名/金额/工期/海拔/日期 → 自动替换
         │
         ▼
  ④ LLM 校验 (单次调用，检查所有章节)
     不重写，只标注问题
         │
         ▼
     最终章节
```

## 三、本地知识库结构

```
~/.bid-archive/                  # 可配置路径
├── archive.db                   # SQLite（全文索引 FTS5）
│   ├── documents                # 每份文档的元数据
│   ├── sections                 # 每个章节（按标题切分）
│   ├── templates                # 泛化后的可复用模板
│   └── FTS5 全文索引            # 内置，零配置
│
├── raw/                         # 原始文件（只读引用）
├── templates/                   # 泛化模板
│   ├── 通用套件/                # 安全/质量/措施/...
│   └── 分部分项/                # 按工种
│
└── parsing_rules/               # 招标解析规则（按地区+评标方式）
```

## 四、匹配实验结果（2026-05-17）

用 13 个已跑项目测试：

| 指标 | 结果 |
|------|------|
| 章节标题匹配率 | 94% (16/17) |
| 项目元数据相似度 | 0.93（同类型棚圈→棚圈） |
| 小节标题重叠 | 0%（LLM 生成措辞每次不同） |
| 内容 4-gram 重叠 | 10-17%（同上） |

**结论**：
- ✅ 元数据匹配精准——项目类型+地区+工种可有效筛选
- ❌ LLM 生成的输出不宜做模板——每次措辞不同
- 🎯 需要用经过审定的真实方案做模板库

## 五、实施计划

### Phase 1: 建库（数据到位后，3-5 天）
1. `batch_index.py` — 批量解析 DOCX/PDF，提取文本+目录
2. `batch_tag.py` — LLM 批量打标（类型/地区/海拔/工种/章节）
3. 写入 SQLite，建 FTS5 索引
4. 人工抽检 5%

### Phase 2: 匹配引擎（1-2 天）
1. `bid_matcher.py` — 结构化筛选 + FTS5 搜索
2. 输出匹配结果 + 置信度

### Phase 3: 模板泛化（1-2 天）
1. LLM 从匹配章节提取通用模板（去项目特征）
2. 按工种+地区变体存储

### Phase 4: 替换+校验（1-2 天）
1. `bid_adapt.py` — 变量替换（纯规则）
2. `bid_verify.py` — LLM 一次性校验所有章节

### Phase 5: 集成（1 天）
1. 改造 `bid_run.py` Step 3，插入匹配→抽取→替换→校验流程
2. 保留 LLM 从零生成作为降级路径（匹配不足时回退）
