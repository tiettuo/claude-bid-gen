## 二、系统设计逻辑验证

**结论：设计方向正确，核心决策经得起验证。**

### 2.1 v2 方法论与行业实践对齐度

| v2 设计决策 | 行业验证 |
|---|---|
| 骨架优先（评分表/大纲/废标先行） | 评标专家第一件事就是"对目录"，章节是否 ∈ 评分表+大纲 |
| 四阶段闭环（抽取→骨架→填充→校验） | 与"初稿-校对-修改-终审"流程对应 |
| 章节锚点 = 评分表 ∪ 大纲 | **所有5个真实项目评分表结构都不同**，无法用固定模板 |
| 三圈字数分配 | 评分制强需求，合格制要求全覆盖 > 字数 |
| 机器校验闸门 | 评标专家的"逐条打勾"行为本质相同 |

### 2.2 跨 5 个项目总结的评标规律

**模式一：合格制——只要大纲列了就必须有**

民房类项目（大纲16项 → 16章） / 学校类项目（大纲要求全部出现） / 仓储类项目B（"其他"被误判为可选，实为锚点）

**模式二：评分制——按分值分配资源，0分项可合并**

环境整治类项目（7项技术标20分 → 按3/3/3/3/3/3/2权重）

**模式三：混合制——施组是否计分决定策略**

仓储类项目B（商务100分+施组合格制0分 → 强制按合格制）

**模式四：废标条款分布规律**

- 投标人须知前附表（p1-30）：报价/工期/页数硬约束集中地
- 评标办法第3章（p50-100）：否决投标条件
- 投标文件格式章（p100-200）：签字盖章/装订/暗标格式
- 最易漏：页数硬顶、底线条款（"不得少于/必须包含"）、兜底否决

## 三、生成质量评审——5类缺陷

### 3.1 🔴 致命：跨项目数据串用

民房类项目输出中整份施组用了养殖类项目的数据。**运行层面路径隔离问题**，非设计缺陷。

### 3.2 🟠 严重：合格制章节锚点 vs writer 调用链脱节

chapter_plan 规划 16 章（1:1对齐大纲），writer 实际只生成 7 章（走了评分制section="技术"路径，忽略了合格制的大纲主题）。

**根因**：writer prompt 构造时对 passfail 模式的章节锚点来源判断有缺陷。

### 3.3 🟡 中等：模板化套话与项目针对性的失衡

- 质量管理/安全管理/劳动力保证 → 高度模板化（任何项目通用）
- 4400m 高海拔施工特殊性 → 有提及但不够具体
- 9户型124户分散施工 → 有提及但未展开
- 80m深井矿山工程 → 浅

### 3.4 🟡 中等：图表功能弱

生成的是 JSON 流程图 PNG，不是工程技术图纸。进度图缺少逻辑关系线，缺失节点详图。

### 3.5 🔵 信息：规范引用

引用了 GB/T 50502 和 DB54 地方标准（正确），但部分编号疑似编造。

## 六、v3 优化路线图

### P0 — 必须修

**跨项目路径隔离**：bid_run.py checkpoint 加入项目指纹校验，每次写操作前验证项目编号/名称一致。

### P1 — 高价值

1. **合格制路径修复**：passfail 时章节锚点强制来自 mandatory_outline.topics
2. **项目针对性增强**：writer prompt 注入 project_brain 第三/四节（重点+难点+约束）
3. **清单→方案映射**：boq.json 反向校验章节覆盖
4. **套话检测器**：自动检测"质量管理体系""安全生产责任制"等模板段落

### P2 — 进阶

5. **工程量驱动展开深度**：量大价高→多字，量小价低→简化
6. **地方标准自动注入**：海拔+区域→自动匹配 DB54 系列
7. **章节内协调一致性**：进度图工期 vs 正文工期 → 机器校验

### P3 — 未来

8. **工艺标准库**：积累成功案例的"标准段落库"
9. **评委视角模拟器**：按评分表逐条预估得分

## 七、总结

bid-gen v2 设计骨架正确，经得起真实项目和行业对照验证。当前最大短板不是设计理念，是**执行一致性**：合格制/评分制路径判断在代码中已有但在 writer 末端可能被绕过，10类隐性知识等待工程化，跨项目隔离需要显式约束。P0-P3 路线图对应约 8-10 个工作日改造量。
