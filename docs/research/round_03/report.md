## 二、核心发现

### 发现 1：「体量 vs 密度」的模型写作悖论（🔴 关键洞察）

通过 V02 (DeepSeek, 38,795 字) vs V03 (Qwen, 22,097 字) 的逐章 P/G 比分析，发现了一个反直觉的模式：

| 指标 | DeepSeek (V02) | Qwen (V03) |
|------|---------------|------------|
| 总汉字数 | 38,795 | 22,097 |
| 项目专用词命中 | 690 | 531 |
| 通用管理词命中 | 988 | 547 |
| P密度（项目词/千字）| **17.8** | **24.0** |
| G密度（通用词/千字）| 25.5 | 24.8 |
| P/G 比（针对性指数）| **0.70** | **0.97** |

**解读**：
- DeepSeek 多写了 16,698 字（+76%），但其中大部分是通用管理语言——P/G 比反而更低
- Qwen 虽然字数严重不足，但每千字中的项目专用词密度比 DeepSeek **高 35%**
- **13/16 章**中 V02 的 P/G 比低于 V03——DeepSeek 的"额外字数"在系统性稀释项目针对性

**这揭示了一个写作质量悖论**：
- DeepSeek = 体量大但稀释（合格的字数，偏低的针对性）
- Qwen = 密度高但体量不足（不合格的字数，合格的针对性）
- 理想状态 = DeepSeek 的体量 + Qwen 的密度

### 发现 2：Ch08（质量管理）存在跨模型模板化（🟡 中等）

Ch08 的首段在 Qwen 同模型（V03 vs V08）间相似度 74%，在 GLM 与 Qwen 间相似度 57-64%。

这说明质量管理章节的开头部分有**结构化模板**——质量管理体系的定义、目标、原则等内容高度可复用。

而 Ch07（施工方案）跨模型首段相似度全部 <50%，说明施工方案内容确有差异。

### 发现 3：套话短语密度低——但检测方法可能偏保守（🟡）

19 类模板短语在 V02 全文中仅命中 13 次（~0.5% 字数）。但这不意味着"没有套话"——现有检测词库过于依赖「制度/体系/责任制」关键词，而实际套话可能是整段通用论述的结构化重复（如"质量是工程的生命…贯彻ISO9001标准…建立三级质量管理体系"）。

需要更高级的检测：**语义模板匹配**（如跨项目的同章节段落语义聚类），而非简单的短语匹配。

### 发现 4：字数稀释主要发生在"制度管理类"章节（🟡）

| 章节 | V02 超 Qwen 字数 | P/G 稀释 | 类型 |
|------|-----------------|---------|------|
| 08_质量管理体系与措施 | +1,194 (+90%) | 0.44→0.53 均低 | 制度管理类 |
| 10_安全文明施工 | +956 (+79%) | 0.29→0.57 稀释 | 制度管理类 |
| 02_编制依据 | +1,276 (+90%) | 0.33→0.59 稀释 | 制度管理类 |
| 15_附图及附表 | +2,016 (+145%) | 1.29→1.33 不稀释 | 附录/杂项 |

**规律**：制度管理类章节（质量/安全/编制依据）中 DeepSeek 额外生成的内容严重稀释项目针对性。施工技术类章节稀释程度较轻。

### 发现 5：项目专用词命中分布不均（🟡）

项目专用词主要集中在 Ch01（工程概况）和 Ch07（施工方案），而 Ch02/08/10 等项目专用词密度极低。这说明 writer 在写管理类章节时**没有充分利用 brain.md 中的项目特殊性**（第三/四节的重点/难点/约束）。

## 四、可操作建议

### P0 — 立即修复

1. **针对 DeepSeek 做「针对性引导」而非限字数**
   - 在 writer prompt 中增加规则："每 500 字必须包含至少 1 个本项目特有的数字/地名/工艺参数"
   - 示例："禁止写'建立健全质量管理体系'而不写具体如何针对 25600㎡暖棚圈的"

2. **Qwen 模型「字数强制」特殊处理**
   - 在 Qwen 的 writer prompt 中大幅提高字数指令的权重
   - 例如："★ 本章硬性要求：至少生成 1,950 个汉字。如你觉得不够，请补充更多技术细节、具体参数、操作步骤、验收标准"

### P1 — 短期

3. **脑→笔连接增强：brain 第三/四节强制注入所有章节 prompt**
   - 当前 writer prompt 包含 brain 全量，但模型可能忽略（注意力稀释）
   - 改为：每章 prompt 的「本章必须包含的项目特征」字段只提取与该章相关的 3-5 条 brain 信息
   - 例如：Ch08 质量管理 → 注入 "高海拔混凝土防冻质量管控（brain 难点1）" "分散作业点质量巡检机制（brain 难点3）"

4. **制度管理类章节的「反模板」规则**
   - Ch02/08/10 等制度管理类章节要求：每个管理体系条款必须有"在本项目中的具体实施方式"
   - 示例：写"三级质量检查制度"后必须跟"针对暖棚圈 16 个分散作业点的具体巡检方案"

5. **建立「章节针对性评分」自动检测**
   - 在 bid_reviewer 中增加 P/G 比检测项
   - 阈值：P/G 比 < 0.5 → minor；< 0.3 → moderate；< 0.2 → major
