# Round 8: 历史项目知识抽取与复用

> 研究日期：2026-05-16
> 数据源：13个完整项目的 output/ 章节文件

---

## 发现

### 1. 可提取知识点规模
跨 13 个项目扫描 6 类高原施工知识：

| 知识主题 | 命中片段数 | 质量评估 |
|---------|----------|---------|
| 高海拔混凝土 | 33 | 🟢 丰富，含配合比/养护参数 |
| 海拔数值 | 20 | 🟢 4500-5373m 跨度大 |
| 暖棚施工 | 16 | 🟢 装配式/基础/墙体工艺 |
| 装配式施工 | 5 | 🟡 可补充 |
| 牧道施工 | 5 | 🟡 可补充 |
| 草皮保护 | 1 | 🔴 严重不足 |

### 2. 知识复用的阻碍
- 所有内容存在于 output/ 章节文件中，但没有结构化的「知识→章节」抽取管道
- 同一主题（如"高海拔混凝土养护"）分散在不同项目的不同章节中
- Writer 无法利用前一个项目的高分段落来生成新项目内容

### 3. 已存在的复用路径
bid-gen-v3 memory/ 目录有 19 个记忆文件，但都是方法论层面的（feedback/reference），而非**内容层面**的（标准段落/技术参数/工艺描述）。

---

## 建议

### P1 — 短期
1. 建立 `memory/vault/` 目录，按工程类型+知识点组织
2. 每个高分章节经 review 后，提取「项目无关」的通用知识点存入 vault
3. Writer prompt 注入与该章节主题匹配的 vault 条目

### P2 — 中期
4. 实现 RAG 机制：writer 写每章时，从 vault 检索 3-5 条最相关的知识片段注入 prompt
