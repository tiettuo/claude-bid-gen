## 二、核心发现

### 发现 1：LLM 系统性编造标准年份版本（🔴 严重）

**GB/T 50502-2009 是施工组织设计的核心国标**，也是 bid-gen-v3 chapter_plan 回落兜底依据。检查发现：

| 引用版本 | 引用次数 | 真实性 |
|---------|---------|--------|
| GB/T 50502（无年份）| 9 | ✅ 合法（缺少年份不违规）|
| GB/T 50502-2009 | 20 | ✅ 真实（目前唯一版本，2009年发布，至今有效）|
| GB/T 50502-**2017** | 2 | ❌ **编造** |
| GB/T 50502-**2019** | 1 | ❌ **编造** |
| GB/T 50502-**2020** | 1 | ❌ **编造** |
| GB/T 50502-**2023** | 1 | ❌ **编造** |

**其他高频编造案例**：

| 标准 | 真实最新版 | LLM 编造版本 |
|------|----------|-------------|
| GB 50300 建筑工程施工质量验收统一标准 | 2013 | 2020, 2023 |
| GB 50204 混凝土结构工程施工质量验收规范 | 2015 | 2023 |
| GB 50303 建筑电气工程施工质量验收规范 | 2015 | 2017, 2020, 2023 |
| GB 50207 屋面工程质量验收规范 | 2012 | 2017, 2023 |
| GB 50345 屋面工程技术规范 | 2012 | 2017 |
| GB 50210 建筑装饰装修工程质量验收标准 | 2018 | 2023 |
| JGJ 59 建筑施工安全检查标准 | 2011 | 2017, 2020 |
| JGJ 46 施工现场临时用电安全技术规范 | 2005 | 2017, 2020 |
| JGJ 104 建筑工程冬期施工规程 | 2011 | 2014, 2017, 2023 |

**根因**：LLM "知道"标准通常会定期修订，因此"推测"存在更新版本，直接编造未来年份。在投标文件中，引用不存在的标准版本 = **严重扣分项**（评委可能判定为虚假响应）。

**估算编造率**：在 352 个唯一标准中，约 **60-80 个（~20%）**存在编造年份版本。在有年份的引用中，编造率可能高达 **30-40%**。

### 发现 2：DB54 西藏地方标准引用严重不足（🟡 中等）

DB54 标准是西藏自治区地方标准，在西藏投标项目中加分权重高。检查发现：

**实际引用的 DB54 标准**（全 13 个项目仅 21 个唯一标准）：

| 标准 | 次数 | 评估 |
|------|------|------|
| DB54/T 0001-2023 高原建筑技术标准 | 8 | ✅ 核心标准 |
| DB54/T 0015-2023 高原建筑施工安全技术规程 | 2 | ✅ |
| DB54/T 0134-2023 | 2 | ⚠️ 编号可疑 |
| 其他 18 个 | 各 1 次 | ⚠️ 多个编号格式不规范 |

**缺失的关键 DB54 标准**（应引用但未引用）：
- DB54/T 0002 — 高原建筑抗震设计（浪卡子/古露/色尼区均为抗震设防区）
- DB54/T 0017 — 高原地区混凝土施工（所有项目涉及混凝土）
- DB54/T 0025 — 高原建筑节能（所有房建项目）
- DB54/T 0136 — 高海拔地区建筑电气（所有含电气项目）

**DB54 编号格式问题**：
- 部分引用写为 `DB540001`（缺少 `/T` 和连字符）
- 部分写为 `DB54/T0001`（格式不一致）
- `DB54/T027-2023` vs `DB54/T0027` 的编号不统一

### 发现 3：GB/T 50502-2009 内容要求 vs bid-gen-v3 实际（🟢 基本对齐）

GB/T 50502-2009 规定的施工组织设计必含内容：

| 规范要求 | bid-gen-v3 覆盖 | 评估 |
|---------|----------------|------|
| 1. 工程概况 | brain 第一节 + Ch01 | ✅ |
| 2. 施工部署 | brain 第三节 + Ch03 | ✅ |
| 3. 施工进度计划 | Ch05 + JSON 进度数据 | ✅ |
| 4. 施工准备与资源配置 | 分散在 Ch02/04/06 | 🟡 部分覆盖 |
| 5. 主要施工方案 | Ch07 | ✅ |
| 6. 施工现场平面布置 | Ch06 | ✅ |
| 7. 主要施工管理计划（质量/安全/环保/成本等）| Ch08-14 | ✅ |

**但是**：bid-gen-v3 的章节锚点是 **评分表∪大纲**，不是 GB/T 50502。当两者冲突时（如西藏简易综合评估法的大纲与 GB/T 50502 结构不同），bid-gen-v3 正确优先跟随大纲——这符合评标规则。GB/T 50502 只在「两者都缺失」时作为最后兜底。

### 发现 4：规范引用缺失「条文号」级别精度（🟡 中等）

所有标准引用均为编号+年份级别（如 `GB 50300-2013`），没有一条引用到具体条文号（如 `GB 50300-2013 第 5.2.3 条`）。在高分投标中，**精准引用到条文号**是加分项——评审专家会认为"这个标书是认真研究过规范的"。

## 四、可操作建议

### P0 — 立即修复

1. **建立标准版本真值表 + 后处理校验**
   - 创建 `configs/standards_truth.json`，收录 80+ 常用标准的真实最新版本
   - 在 `bid_compliance.py` 中增加「标准引用校验」检查项
   - 对编造年份的标准自动替换为真实最新版本（或标记警告供 LLM 处理）

2. **为 writer prompt 注入「禁止编造标准年份」约束**
   - 增加规则："引用标准时只使用以下格式：`GB 50300-2013`。如不确定年份，则省略年份写 `GB 50300`"
   - "不要推测标准是否有更新版本——只引用你确认存在的版本"

### P1 — 短期

3. **建立 DB54 标准自动注入机制**
   - 根据 brain.md 中的海拔等级（extreme/high）和项目类型，自动注入适用 DB54 标准清单
   - 例如：海拔 extreme → 注入 DB54/T 0001 + DB54/T 0017 + DB54/T 0025

4. **标准引用提升到条文号级别**
   - 在 writer prompt 中要求引用到具体条文号（`GB 50300-2013 第 5.0.4 条`）
   - 这需要将条文号注入 prompt 的参考材料——因为 LLM 自己不知道具体条号

5. **合规扫描增加「标准编造检测」**
   - `bid_compliance.py` 读取 standard_truth.json
   - 对每个引用的标准：检查版本是否存在、编号是否合法
