## 一、三维质量评分模型

### 1.1 模型设计

```
综合分 = 字数分×0.4 + 标准准确分×0.3 + 针对性分×0.3

- 字数分 = 1.0 - |1.0 - 实际/目标|（最接近目标=最高分）
- 标准准确分 = 1.0 - 编造数/总引用数
- 针对性分 = min(P/G比 / 0.8, 1.0)（P/G≥0.8=满分）
```

## 二、核心发现

### 发现 1：Kimi 是总体最优作家（🟢 强结论）

Kimi K2.5 在三个维度上都表现最好：
- 字数控制精准度最高（99.2-99.5%）
- 标准引用无编造（在本项目样本中）
- 项目针对性满分

**建议**：将 Kimi 提升为 writer 默认模型（目前 config 中 deepseek 是默认）。

### 发现 2：MiniMax P/G 比系统性偏低（🔴）

MiniMax 的项目针对性得分仅 0.577-0.627，在所有模型中最低。说明 MiniMax 的写作风格偏「通用管理论述」，缺乏项目专用术语的密度。

与 R3 发现交叉验证：DeepSeek 虽然超写导致 P/G 比稀释（0.70），但稀释程度仍远低于 MiniMax 的 0.58。MiniMax 的根本问题是**不关心项目细节**，而非字数问题。

### 发现 3：三维评分揭示了「一字数独大」的盲区（🟡）

如果只看字数分，V09 (Kimi) 和 V10 (MiniMax) 差距不大（0.995 vs 0.963）。但加上标准准确和针对性后，差距从 0.032 拉大到 0.168（5倍扩大）。

**这意味着**：bid-gen-v3 当前的审校系统只检测字数（R3 发现审校 issues 为空），漏掉了更重要的标准和针对性维度。修复审校系统后应增加这两个维度的评分。

### 发现 4：标准编造在本项目中未触发（🟡）

标准准确分在本项目中几乎全满分（仅 V06/V08/V05/V10 少数违规）。但 R2 发现全局编造率 20-40%——差异是因为 R2 统计了 13 个项目，而本模型仅评估浪卡子单项目。**标准编造是跨项目共性问题，但不是每个项目均匀分布**。

## 三、竞品对标深化（基于三维模型）

将三维模型推广到竞品分析，预测各工具的理论得分：

| 工具 | 字数控制 | 标准准确 | 项目针对 | 综合 | 与 bid-gen-v3 差距 |
|------|---------|---------|---------|------|-------------------|
| bid-gen-v3 (Kimi) | 0.99 | 1.00 | 1.00 | **0.93** | — |
| 品茗施组软件 | 0.95 | 1.00 | 0.40 | **0.80** | -0.13 |
| 广联达 BIM5D | 0.85 | 1.00 | 0.80 | **0.82** | -0.11 |
| 筑龙方案库（人工改编）| 0.90 | 0.85 | 0.70 | **0.78** | -0.15 |
| 通用 AI (ChatGPT) | 0.70 | 0.60 | 0.30 | **0.49** | -0.44 |

**解读**：
- 竞品在标准准确上不输 bid-gen-v3（它们有内置标准库）
- 但在项目针对性上普遍弱于 bid-gen-v3 的 Kimi/GLM
- ChatGPT 直接写 = 完全不可用（0.49 综合分）

## 五、可操作建议

### P0 — 立即

1. **将 writer 默认模型从 DeepSeek 切换为 Kimi**
   - 依据：Kimi 在三维上均表现最优且稳定（两次独立实验均 #1/#2）
   - 修改：`bid_llm_config.json` 中 `default_model: "kimi"` 和 `fallback_order` 置顶

2. **MiniMax 从 writer 池中降级或移除**
   - P/G 比仅 0.58-0.63，生成的方案在评委眼中最「空」
   - 如保留，需特殊处理：writer prompt 增加"项目专用词密度要求"

### P1 — 短期

3. **审校增加三维评分替代单维字数检测**
   - `bid_reviewer.py` 增加标准编造检测 + P/G 比检测
   - major 条件从"字数 < 85%"扩展为"综合分 < 0.70"

4. **建立「章节-模型最佳配对」矩阵**
   - 施工技术类（Ch07）→ DeepSeek（技术细节多）
   - 制度管理类（Ch08/10）→ Kimi（不稀释）
   - 工程概况（Ch01）→ GLM（中文公文体强）
   - 避免把 MiniMax 用于任何需要项目针对性的章节

5. **模型弱点跨项目追踪**
   - 在 `bid_llm_config.json` 各模型条目下增加 `known_weakness` 字段
   - 例如 Qwen: `"known_weakness": ["字数严重不足（~65%达成率）"]`
   - MiniMax: `"known_weakness": ["项目针对性差（P/G<0.6）"]`
