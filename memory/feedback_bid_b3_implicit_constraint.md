description: bid_skeleton_extract.py 的 B3 prompt 关键词清单只覆盖"结果性触发词"(否决/废标/无效),漏掉"约束性触发词"(不得超过/必须),导致页数硬顶 70 页这类条款被漏抽
type: feedback
session: 已脱敏

写施组前,在生成 brain.md 第六节"废标条款"和 disqualification_rules.md 时,**不能只信 disqualification.json**,必须手工去原文核对一类容易被漏的条款:**隐含废标后果的硬约束**。

**易漏类型(disqualification.json 通常抽不到):**
- 页数硬顶("总页数不得超过 70 页")
- 字数硬顶("章节不得超过 N 字")
- 装订/排版硬性参数(若违反某项明确写"视为不响应",经常被埋在格式说明里)
- "不得少于 N""至少包含""必须涵盖" 类语言
- 投标保证金有效期/递交方式("应于...前到达" 等绝对要求)

**Why:** B3 prompt(`Claude Code 脚本目录/bid_skeleton_extract.py:485-491`)关键词清单只有 13 个,全是结果性触发词:
```
「否决投标」「废标」「无效投标」「不予受理」「限制参加」「视为撤销」
「视为不响应」「重大偏差」「实质性偏差」「直接否决」「一票否决」「按废标处理」「视为无效」
```

招标文件常把硬约束写成"**不得超过 X**""**必须 Y**",**字面不出现废标关键词**,LLM 按 prompt 走就漏抽。但实质后果是这些约束违反了会触发兜底条款"未响应实质性要求 → 智能化招投标电子交易系统否决投标"(招标常见 p58/p60)。本项目棚圈类项目 2026-05-10 实测:p22 第 10.16 款第 3 项"中小型项目总页数不得超过 70 页"漏抽,差点按 170 页规划。

**How to apply:**
1. Step 2 写 brain 第六节 + chapter_plan 总量预算前,**手工搜 .txt 关键词**:`grep -nE "(不得超过|总页数|不得少于|必须包含|必须涵盖|至少|不得彩色|不得使用|应当|应于.*前|视为)"` "File_*招标文件*.txt"
2. 重点扫两片区:
   - 投标人须知前附表(通常 p7-30) — 报价/工期/解密/页数硬约束多在此
   - 评标办法前附表 + 详细评审章 — "未响应实质性要求"自动否决的兜底
3. 把漏抽的条款手工补入 brain 第六节和 disqualification_rules.md,标明 `[来源: 文件名 pXX]`
4. 长期修复方向:B3 prompt 增加"约束性触发词" + 新增类别"硬约束"(暂未做)

**历史背景:** 学校类项目同样 70 页硬顶(memory `私有项目归档`),那是西藏自治区招投标系统固定模板。棚圈类项目是同一模板再现 → 西藏那曲 / 简易综合评估法-自主定标 类项目几乎都有这条 70 页硬顶。
