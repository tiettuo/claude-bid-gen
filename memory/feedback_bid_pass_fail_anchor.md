bid-gen 项目，**当 `disqualification_rules.md` 中 `tech_evaluation_method: 合格制`（或 `tech_total_score: 0`）时**，brain.md 第七节解析出的施组编制大纲一级主题必须**逐项独立成章**，不允许合并、不允许吸收到他章末段、不允许标"可选"省略。

**Why（错误教训，2026-05-04 仓储类项目B项目）：**

招标第七章原文 16 项主题（…15 附图及附表 / 16 其他）。我前次会话错误判断「16 其他」为可选项，主观决定"吸收为各章末段不独立成章"，把 chapter_plan 缩成 15 章，rules.must_include_sections 跟着同步成 15 项。结果两份骨架文档自洽通过，但根本是**扫描标准就少了一项**——评委按章节标题逐项核查"是否合格"，找不到「16、其他」=不响应实质性要求=废标。

错误的根本原因：**在合格制项目里套用了评分制思维**。评分制下"0 分项可省"成立，因为评委按分值找；合格制下评委按主题字面找，缺一项即视为不响应。我当时还叠加了一层"70 页硬顶要省页数"的页数焦虑，让"省可省"凌驾于"全覆盖底线"。

**How to apply：**

1. 进 Step 2 后第一时间看 `disqualification_rules.md` 的 `tech_evaluation_method` 和 `tech_total_score`：
   - 合格制 / total_score=0 → 接下来按本条规则操作
   - 评分制 → 0 分项可酌情合并（仍不建议主观省略）

2. 合格制下生成 chapter_plan 时硬性要求：
   - chapter_plan 章节数 ≥ brain 第七节主题数（除招标显式标注"X 项可选"）
   - rules.must_include_sections.sections 项数 = brain 第七节主题数（1:1 同步）
   - 三份文件（brain / rules / chapter_plan）数字必须一致——任意两份不同步即视为我犯了主观删项错误，立刻补回

3. 页数硬顶时的优先级（合格制）：**全覆盖 > 单章字数 > 页面美观**。宁可把每章压缩到下限 85%（避开格式废标）也不得砍掉大纲主题成章

4. bid_plan_verify 输出 WARN "大纲主题未在 chapter_plan 找到"时，**合格制下视同 ERROR**——立刻补章节，不允许"人工确认省略"越过

5. "其他/补充事项/备注/附录"这种看似兜底的章名是合格制评委的常用核查锚点，绝不省

**升级：二级三级节也要 1:1 保留（2026-05-07 民房类项目项目教训）**

不仅一级主题要 1:1，**招标第七章下设的二级节（如「第一节 建筑工程 / 第二节 机电设备及安装」）和三级节（如建筑工程下「1.土石方开挖 / 2.脚手架工程 / ... / 9.节能工程」）也必须 1:1 保留为子节标题**。

具体策略（用户提出，已验证）：
- 节标题严格按招标第七章原文 1:1 抄录（让评委按目录找得到）
- 正文按"清单实事求是"取舍，每个子节打 ★/○/△ 标签：
  - **★ 实质**：清单有明确对应分部 → 400-800 字技术方案
  - **○ 简化**：清单部分涉及但量小 → 100-300 字简明要点
  - **△ 不涉及**：本项目工程构成无该项 → 60-100 字"本项目不涉及"说明 + 理由
- 这样既覆盖目录（合格制），又避免无中生有触发 B1.17"明显不符合技术规范"

避免的反面：
- 砍掉招标第七章列出但本项目无对应内容的子节（如本项目无暖廊、无大型钢结构、无镀锌钢管管网） → 评委按目录找不到 → 不合格风险
- 强行展开本项目无对应内容的子节（如让本项目编造"大型钢结构施工方案"） → 触发 B1.17 不符合技术规范
