招标文件给页数硬顶时常用"大型复杂项目（如高层建筑、桥梁等）≤100 页 / 中小型项目（如普通住宅、厂房等）≤70 页"这种**例举式**约束。本项目类型一旦不在例举（如水电气路、市政管廊、土地整治），Claude 必须按矩阵自动判档，不要让用户从零选。

**判档矩阵：**

| 维度 | 中小型 | 大型复杂 |
|---|---|---|
| 招标控制价 | < 1000 万 | ≥ 1000 万 |
| 工期 | < 270 天 | ≥ 270 天 |
| 工程类型 | 普通住宅/厂房/单层建筑/小型市政/水电气路配套 | 高层（≥10 层）/桥梁/隧道/地铁/电厂/大型场馆/大型水利 |
| 单专业体量 | 管线 < 5 公里 / 混凝土 < 5 万方 / 装机 < 10MW | 反之 |

**判档规则：**
- 4 项中 ≥3 项判中小 → 中小型，70 页
- 4 项中 ≥3 项判大型 → 大型复杂，100 页
- 平局（2:2）→ 取保守值（中小型 70 页），评委按"未超页"判合格风险更低

**Why:** 判错的代价不对称——
- 判 100 实际写 70 → 篇幅过大，关键页码错位 + 装订臃肿
- 判 70 实际写 80 → **直接超页废标**

判保守（70）只损失"少写 30 页"，判激进（100）超标即废。**默认按中小型判**。

- chapter_plan 第一圈直接给"判档矩阵 + 结论 + 硬顶"，不要"二选一"
- brain.md 第七节排版段把"二选一"原文改成 4 行判档表格 + 结论
- 学校类项目 70 页 / 这次水电气路 70 页 = 都按矩阵判中小型保守
