**2026-09-27 某藏北乡镇派出所改扩建项目（767.04㎡，合格制，70页硬顶）实测：**

该清单 xlsx 有 **7 个单位工程**（`表02-1 工程项目费用汇总表` 第 1~7 行）：

| 单位工程 | 工程规模 | 专业 |
|---|---|---|
| 办案用房改造工程 | 165.00 | 建筑装饰/安装/采暖通风 |
| 业务保障用房改造工程 | 150.26 | 建筑装饰/安装/采暖通风 |
| 阳光棚改造工程 | 280.80 | 建筑装饰/安装 |
| 备勤用房工程 | 437.22 | 建筑装饰/安装/采暖通风 |
| 旱厕工程 | 14.56 | 建筑装饰/安装 |
| 新建大门工程 | 13.26 | 建筑装饰/安装 |
| 附属工程 | — | 市政工程/安装 |

xlsx 里同名单位工程会出现 `建筑装饰工程` / `建筑装饰工程(1)` … `(5)` 后缀，**每个都是独立单位工程**，不是重复 sheet。

**问题：** `bid_brain_translate` 第 2 节「工程构成」是拿 `boq.json` 的 23 个**专业类目**（混凝土及钢筋混凝土工程 / 屋面及防水工程 / …）铺开的。结果 16 章正文**从头到尾没有出现过任何一个单位工程名**（案件房、阳光棚、备勤用房、旱厕、大门、附属工程），我全章 grep 才查出来。招标范围原文是"总建筑面积 767.04 平方米及附属配套设施"，方案不提子项名 = 评委无法确认覆盖面。

**How to apply：**
1. Step 2 生成/审阅 brain 后，`grep 表02-1` 抽出单位工程表；若 >1 个单位工程，必须在 **brain 第 2 节 + chapter_plan 的工程概况章**写入单位工程表（序号/单位工程/工程规模/专业构成），并在施工方案章开头引入"按 N 个单位工程组织"。
2. 表02-2 名称带的 `(n)` 后缀原样保留，作为单位工程标识符。
3. 不要把「工程规模」求和后当成总建筑面积——本案 7 项求和 1,061.10 ≠ 招标公告的 767.04 ㎡（口径不同：改造类按改造面积计）。只按清单口径逐条列，不做加总断言。
4. 单位工程名往往能揭示真实技术特征：本案「阳光棚改造工程 280.80」正好等于清单"5厚耐力板屋面 280.8m2"——原本被 brain 当成"耐力板屋面重点"，补上单位工程后才说清那是阳光棚顶。

**待办：** 上述应在 `bid_boq_extract.py` / `bid_brain_translate.py` 里固化（解析 `表02-1`/`表02-2` 的表头写 `boq.json.units`，brain 第 2 节优先按 units 铺开），目前是交付阶段人工补写。
