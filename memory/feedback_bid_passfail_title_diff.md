**2026-09-14 谢通门县周转房（6 标段，三家批量）用户反馈：**"这个标题完全一样，肯定会被判为串标"。

**背景：** 为实现 `feedback_bid_pass_fail_anchor.md` 的"大纲二/三级节 1:1 保留"，`bid_plan_variants.py` 在合格制下曾**直接锁定基准子项并跳过 LLM 切分** —— 结果三家 H1/H2 标题**逐字相同**，只有正文不同。合格制下 `bid_similarity.py` 的标题骨架顺序相似度一度达 96–99%（阈值 70%）。

**判断：** 两件事都要满足，不能二选一 ——
- 大纲主题/节标题是评委逐条核查的锚点，**集合不能变**（不增、不减、不换义、不改顺序）
- 但**字面必须三家不同**：评标实践中"章节标题逐字相同"是围标/串标的高危表征，比正文雷同更直观

**How to apply（已在 `bid_plan_variants.py` 落地）：**
1. `style_passfail_chapter_titles()`：一级章标题按变体风格改写（第 1 家原文；第 2 家"原主题词+限定语"；第 3 家"工程化表述"）。
   **硬校验（2026-09-14 加严，替代旧口径）**：改写后的标题必须**把原标题整串作为子串包含**（去空白比较），且长度不超原题 +14 字、不得带「（补充说明）/（含实施细则）/（实施要点）」括号后缀。
   旧口径"保留前 2 字 + 汉字重合 ≥50%"**不够**：它放过了「质量管理体系与措施」→「质量管理体系与**保证**措施」、「季节性施工措施」→「季节性施工**技术**措施」这类丢词/插词改写（实测 7 处），评委按招标大纲字面核对会找不到对应章 = 不响应风险。
   未过校验或与先前变体撞车的条目：再问一次 LLM（明确"原标题必须原样保留"）→ 仍不行则**回退原文**；**不得**用括号后缀硬凑（旧实现造成同一份目录反复出现「（补充说明）」，实测 V03 出现 7 次，本身即机器痕迹）。
   避撞清单 `_pf_h1_taken` / `_pf_h2_taken` 必须**按章分桶**：同名子项（如「编制依据」）会跨章重复出现，扁平 list 会把跨章同名误判为撞车。
2. `style_passfail_titles()`：二级子项同样按风格改写；改写时把**先前变体已用的措辞**作为"已占用"清单传给 LLM，并对撞车条目做确定性回退（`（含实施细则）`/`（实施要点）` 后缀）。
3. 编号体系轮换：`1.1` / `一、` / `（一）`（`_NUM_STYLES`）；标题内层编号（`第X节`、`1、`）先剥离，避免"一、第一节 建筑工程"式双重编号。
4. 三家目录雷同度自检：`python3 -c` 比对三家 `chapter_plan_variant.md` 的 H1/H2 同名率，应 <20%（残余同名只会是"土石方开挖"这类招标原文短词，属正常）。

**验证结果（谢通门周转房 7 标段，2026-09-14 终态）：**
- H1：V02 14/16、V03 10/16 与原主题不同，**三家家家互不相同（0 处重复），且 0 处丢原词**（原主题始终是新标题子串）
- H2：三家集合重合 3%；`heading_set` 3%、`heading_order` 6%（阈值 0.85/0.70）——旧版为 100%/100%
- 正文 overall 3.2–5.4%、段落最大 13–29.7%；DOCX 元数据（creator/lastModifiedBy/created）三家全不同
- 合规扫描 0 问题、评标专家 fatal 0、页数 58.9–68.9（硬顶 70）
- 大纲 16 项仍全部命中，合规退出码 0
- **提交件（DOCX）实测**：段落近重复 0.0%，8-gram Jaccard 0.8–1.3%

**同时记住两个测量口径陷阱：**
- `bid_similarity.py` 的"段落最大重复率"把 ` ```json ` 图表块当正文段落比，三家图表 schema 同构必然 55%+ → **误报**。DOCX 里 JSON 已被渲染成图片、根本不存在，判定串标应看**产物级**文本。
- 专家评审工具在混合制项目里会拿商务标评分项（报价/业绩/班子）去评技术章 → 分数无意义，只看它的"跨章一致性"部分。

**升级（2026-09-14 同日，用户第二条反馈）：二级标题"数量"也不能三家一致**

用户查看后指出："二级标题的数量是一样的，这个也不符合逻辑"。三家每章 15/5/5/4… 一一对应，本身就是"同一模板套出来"的痕迹。

**做法（大纲条目一条不丢 = 覆盖底线，但分节粗细三家各异）：**
| 变体 | H2 数量 | 层级 | 大纲 111 条去向 |
|---|---|---|---|
| V01 | 111 | 每条目一个 H2 | 直接作 H2 |
| V02 | 60 | 每 2 条并 1 节 | 降为 H3（逐字保留） |
| V03 | 42 | 每 3 条并 1 节 | 降为 H3（逐字保留） |

- 分组标题由 LLM 拟（4-14 字主题名，如「项目概况与施工条件界定」）；分组本身用**确定性顺序切分**（LLM 自由分组会产生重叠/漏项，实测踩坑：`range` 末位 `+1` 的 off-by-one 导致每组多吃 1 条）
- 覆盖不受影响：大纲条目仍逐字出现在 H3，评委按目录仍能找到；`check_outline_coverage` 只看 H1+H2 的 16 个一级主题，仍全部命中
- 变体计划的子项清单必须同步改成"分组标题 + 合计字数"，否则 reviewer 的 subitem 1:1 核查会报 mismatch

**终态（本次交付，DOCX 实测）：**
- 结构：V01 = 16 H1/111 H2/0 H3；V02 = 16/60/111；V03 = 16/42/111
- 标题骨架相似度：0.00/0.00、0.00/0.00、0.02/0.01（阈值 0.70/0.85）
- 整体文字重复率 0.07–0.27；DOCX 段落近重复 0.0%

**待办（诚实记录）：** 上述"分组降级"目前是交付阶段的**后处理脚本**（按 `/tmp` 临时脚本执行），尚未固化进 `bid_plan_variants.py`。若要流水线原生支持，需给 writer 增加"分组 H2 + 条目 H3"的提示模式（现 writer 只支持"N 个 H2 平铺"），否则新跑一遍仍会回到"三家 H2 数量一致"。

**升级（2026-09-14 晚，用户第三次反馈）：二级标题"数量"也不能三家一样 + 严禁双序号**

用户原话："二级标题的数量不能完全一样，且二级标题出现了双序号"。两条都是真问题：

**1. 数量一致本身就是痕迹。** 三家 H2 都是 83 个（大纲二级节 1:1 的直接后果），目录一眼同源。终态做法：
- V01 = 83 个（大纲原文，1:1）
- V02 = **44 个**（同章相邻二级节**合并**：首条改为合并标题，次条降级为正文里的 `**加粗小标题**`，内容一字不丢，术语仍在文中可检索）
- V03 = **101 个**（把原有三级节 `###` 全部**提升**为二级节 `##`，层级更平）
- 三家数量必须互不相同；合并标题用 LLM 拟制（要求同时体现两条的核心名词、8-22 字、无序号无括号）

**2. 双序号是组装器与标题文本的冲突。** `bid_charts._normalize_heading_numbers()` 会**自动剥离标题自带编号并按变体编号风格重排**（A–L 风格，各家不同）→ 若标题文本里又自带 `一、`/`（一）`，成品就成 `（一） （一）工程概况…`（实测 V03 全篇）。
**规则：H1/H2 标题文本内一律不得自带编号**，编号完全交给组装器 + `_HEADING_STYLES` 的变体风格（阿拉伯 `1.1` / `一、` / `（一）`），差异由组装器提供，不要在标题里重复。

**终态验证（谢通门周转房 7 标段）：** H2 数量 83/44/101；`heading_set` 0–3%、`heading_order` 0–5%（阈值 0.85/0.70，旧版为 100%/100%）；正文 overall 3.2–5.1%、段落 13–29.7%；合规 0 问题、专家 fatal 0；页数 58.9–68.7（硬顶 70）。

**注意：** 层级重构（合并/提升）只动标题行、不动正文，因此页数与已通过的合规/相似度结论仍成立；但重构后**必须重跑 bid_reviewer**（H2 1:1 是拿变体计划核对的，计划里的子项列表与字数要同步重写，字数按各二级节实际正文长度比例缩放回章节目标）。

**补充（2026-09-16 尼木民宿项目）：H1 变体标题会带回提示词里的序号前缀。**
`style_passfail_chapter_titles()` 的 prompt 把待改写标题按 `1. xxx / 7. xxx` 编号列出，模型对**后面的条目**会连序号一起回显（本项目 V02 章 07–14、V03 章 05/08/10/11 变成「6. 施工方案与技术措施专项策划」…）。后果：`bid_plan_variants` 把它写进 `chapter_plan_variant.md`，writer 逐字照抄成 H1，DOCX 目录出现「第八章 7. 质量管理体系与措施实施要点」这种双序号（与上面第 2 条同源缺陷，只是发生在**生成阶段**而不是组装阶段），并且 `bid_plan_verify`/`bid_compliance` 拿计划核对时会**以错核错**（两边都有 `6.` 就判"对齐 ✓"），只有人眼看目录才发现。
**已修：** `cand` / 重试 `_c2` 两条路径都过 `strip_inner_number()`（该函数已在子项标题路径用了很久）。修后必须**同时**改计划文件和章节 H1——只改一边会被 compliance 判"标题不一致"（本轮就是这么踩的：先改 H1 → compliance 报 8 条不一致 → 再改计划 → 通过）。
