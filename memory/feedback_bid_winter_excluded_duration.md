---
name: 工期不含冬季停工期时的进度口径
description: 招标写「工期 N 日历天（不含冬季停工期）」时，冬歇必须排除在工期之外；进度图文里要显式给出"有效施工天 + 冬歇天 = 日历跨度"的口径说明，否则评委可判工期响应不实
type: feedback
---

西藏/高原项目常见的工期表述是：

> 计划工期：240日历天，（自招标人正式发出的开工令载明的开工之日起算，**不含冬季停工期**）

**这不是"工期 240 天，中间有 60 天停工"，而是"有效施工 240 天，冬歇另计"。**

正确的进度编排列式：

```
开工后第1至90天      冬歇前有效施工期（计入工期）
第91至150天          冬季停工期（60 天，不计入工期）
第151至300天         复工后有效施工期（计入工期）
有效施工 = 90 + 150 = 240 有效日历天
实际日历跨度 ≈ 300 天
```

**错误写法（某西藏施组项目首版踩过）：** 把 240 天当成"含冬歇"的总轴，
冬歇排在第 91–150 天、复工后排到第 240 天结束。结果是有效施工只有
90+90=180 天，**工期响应少 60 天**，且与招标"不含冬季停工期"直接冲突。
`bid_expert_review` 的跨章一致性检查稳定命中：
「招标口径240天不含冬歇，章05却将60天冬歇纳入240天横道图」。

**How to apply:**
- `bid_writer` 写 `05_施工总进度计划.md` 时，横道图 JSON 的日序用**日历天**，
  但在 `title`/`note` 里写清口径：`第1至90天 + 第91至150天(冬歇，不计入) + 第151至300天 = 240 有效日历天，日历跨度 300 天`。
- 冬歇期在 JSON 里作为一条 task（phase="冬歇"）保留，让评委看得见停工，
  但名称直接标注「冬季停工期（60天，不计入240日历天工期）」。
- AOA 网络图的时长字段用**有效施工天数**，冬歇用 `duration: 0` 的占位活动
  （渲染器支持 0 时长，`_critical_path` 用 `a.get("duration", 0)`），
  使关键线路总和正好等于招标工期。
- **所有跨章引用同一批日序**：01 工程概况、04 组织协调、09 工期保证、
  11 绿色施工、12 季节性、15 附表四，都要按同一套有效天/日历天口径同步改，
  改完必须重跑 `bid_expert_review` 看跨章条目是否归零。
- 判据：`Σ(关键线路有效时长) == 招标工期`，且 `Σ(日历跨度) == 工期 + 冬歇天数`。

**某西藏施组项目复核数据（2026-09）：** 工期 240 天不含冬歇、海拔 3820m、跨冬。
定稿采用 90（冬歇前）+ 150（复工后）= 240 有效天，日历跨度 300 天。
